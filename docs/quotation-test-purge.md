# 일반 Quotation 테스트 견적 완전 삭제

일반 Quotation 목록과 상세 화면의 `테스트 견적 완전 삭제`에서 사용합니다. RED Quotation에는 적용하지 않습니다.

## 운영 적용

1. 기존 일반 견적 무결성 SQL(20261101000100)이 적용되어 있어야 합니다.
2. 같은 운영 Supabase 프로젝트의 SQL Editor에서 `quotation-test-purge-setup.sql` 전체를 새 쿼리에 붙여 넣고 실행합니다. 마지막 `commit;`까지 포함합니다.
3. 성공 결과를 확인한 후 이번 코드 변경을 배포합니다.

설정 SQL은 삭제 기능을 설치합니다. 실행만으로 기존 견적을 삭제하지 않습니다. 기존 견적번호를 예약하여 완전 삭제 후에도 번호가 재사용되지 않습니다.

## 사용 방법과 경고

1. 삭제할 테스트 견적에서 `테스트 견적 완전 삭제`를 누릅니다.
2. 실제 견적번호, 바이어, 제목과 삭제할 버전·견적 행·첨부 기록 수를 확인합니다.
3. 견적번호를 직접 입력하고, `테스트용 견적이며, 삭제 후 복구할 수 없음을 확인했습니다.`를 체크합니다.
4. `복구 불가 · 완전 삭제`를 누릅니다.

경고: **이 작업은 되돌릴 수 없습니다. 해당 견적의 모든 버전·스타일 행·수량별 가격·첨부 기록을 완전히 삭제합니다. 보관함에서도 복원할 수 없습니다.**

모든 버전이 초안이어야 합니다. 발송·확정 이력이 있거나 다른 견적/업무에서 참조하는 견적은 서버에서도 삭제를 차단합니다. 일반 견적 삭제 권한이 필요합니다. 원가표 원본은 삭제하지 않습니다. 기존 보관/복원 기능도 유지됩니다.

## 파일과 실패 처리

견적 레코드는 한 DB 트랜잭션에서 삭제합니다. 중간 오류가 나면 전체 삭제를 취소합니다. 미리보기 이후 내용이 바뀌면 재확인을 요구합니다.

첨부 원본은 견적 삭제 성공 후 별도 요청으로 정리합니다. 다른 견적이 참조하는 공유 파일은 보존합니다. 정리가 실패하거나 한 번의 처리량을 초과하면 완료 창 또는 목록의 `첨부파일 정리 재시도`에서 이어서 처리합니다. 중단된 파일 작업은 2분 임대 만료 후 다시 처리할 수 있습니다.

번호 재사용 방지용 번호·ID 예약과 파일 정리 작업 메타데이터는 남습니다. 삭제된 견적의 가격/버전/문서 데이터는 남기지 않습니다.

## 검증

- 앱 회귀 테스트 129개 통과
- 삭제 확인 UI 상호작용 테스트 4개 통과 (Dialog 컨테이너 대체)
- 로컬 PostgreSQL 호환 엔진에서 삭제 DB 검증 21개, 기존 일반 견적 19개, RED 견적 18개 통과
- 삭제 SQL 재실행, 원자적 롤백, 발송/참조 차단, 번호 재사용 방지, 파일 공유/재시도 및 클라이언트 권한 차단 검증

운영 데이터 삭제 및 운영 Storage 삭제는 실행하지 않았습니다. 전체 Next 빌드는 기존 Windows 쓰기 권한 문제로 로컬 검증되지 않았으므로 배포 빌드 성공도 확인해야 합니다.
