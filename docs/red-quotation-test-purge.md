# RED Quotation 테스트 견적 완전 삭제

RED 목록과 상세 화면에 `테스트 견적 완전 삭제`를 추가했습니다. 기존 Archive/Restore도 사용할 수 있습니다. 삭제 권한이 있는 직원만 버튼을 볼 수 있습니다.

## 운영 적용

운영 Supabase의 기존 RED/일반 견적 무결성 설정은 이미 적용되어 있어야 합니다.

- 일반 견적 완전 삭제 SQL을 아직 적용하지 않았다면 `quotation-all-test-purge-setup.sql`을 SQL Editor 새 쿼리에서 전체 실행합니다. 일반과 RED 기능을 함께 설치합니다.
- 일반 삭제 SQL을 이미 적용했다면 `red-quotation-test-purge-setup.sql`만 실행해도 됩니다.
- 성공 결과를 확인한 다음 이번 코드 변경을 배포합니다. SQL만 실행해서는 화면 버튼이 추가되지 않습니다.

두 파일은 기존 견적을 자동 삭제하지 않습니다. 번호 예약과 기능 설치만 수행합니다. 통합 파일은 두 트랜잭션으로 구성되어 있으며 재실행 가능합니다.

## 삭제 확인

삭제 창에 견적번호·바이어·제목·버전/가격/이미지 기록 수가 표시됩니다. `이 작업은 되돌릴 수 없습니다.`와 보관함에서도 복구할 수 없다는 경고가 나옵니다. 견적번호 직접 입력과 복구 불가 확인 체크를 마쳐야 `복구 불가 · 완전 삭제` 버튼이 활성화됩니다.

모든 버전이 DRAFT이고 발송/확정 이력이 없어야 합니다. 과거 버전이 발송되었다면 최신 버전이 DRAFT여도 차단합니다. 다른 업무/견적의 외래키·RED 연결이 있거나 서로 다른 견적의 자료가 섞여 있으면 차단합니다. 미리보기 후 내용이 변경되어도 재확인을 요구합니다.

삭제는 한 DB 트랜잭션으로 RED 헤더·버전·문서·기존 가격 매트릭스·원가 입력·포장비·이미지 기록을 정리합니다. 중간 오류면 전체 취소됩니다. 원가표나 다른 업무의 원본을 삭제하지 않습니다. 견적번호는 다시 사용하지 않습니다.

이미지 원본은 견적 삭제 성공 후 별도 요청으로 정리하며, 다른 RED 견적에서 참조하는 공유 이미지는 보존합니다. 실패/처리량 초과 시 완료 창 또는 목록에서 재시도합니다. 중단된 작업은 2분 임대 만료 후 다시 시도할 수 있습니다. 삭제번호 예약과 이미지 정리 메타데이터는 남습니다.

## 검증 범위

앱 회귀 테스트 140개, 삭제 창 상호작용 5개(Dialog 컨테이너 대체), RED 삭제 DB 검증 14개를 통과했습니다. 일반/RED 통합 SQL을 로컬 DB에 두 번 적용해 재실행 가능함을 확인했습니다. 타입 검사도 통과했습니다.

운영 견적 삭제나 운영 이미지 삭제는 실행하지 않았습니다. 기존 Windows 쓰기 권한 문제로 전체 로컬 Next 빌드 검증은 완료하지 못했으며 배포 빌드 성공 확인이 필요합니다.
